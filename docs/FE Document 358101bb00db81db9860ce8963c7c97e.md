# Frontend Architecture - ManabiHub

# 1. Mục tiêu của frontend

Frontend của ManabiHub chịu trách nhiệm xây dựng giao diện cho các nhóm người dùng:

```
Guest
Student
Teacher
System Admin
```

Frontend không chỉ là giao diện hiển thị. Nó còn chịu trách nhiệm:

```
Điều hướng người dùng
Hiển thị đúng màn theo role
Gọi API backend
Validate form trước khi gửi
Hiển thị lỗi theo messageCode
Quản lý loading/error/success state
Tách layout Public, Student, Teacher, Admin
```

---

# 2. Công nghệ frontend

Frontend sử dụng:

```
React
TypeScript
Vite
Tailwind CSS
React Router DOM
Axios
TanStack Query
React Hook Form
Zod
```

Ý nghĩa:

```
React:
Xây dựng UI component.

TypeScript:
Giảm lỗi type, giúp code rõ ràng hơn.

Vite:
Dev server/build tool nhanh.

Tailwind CSS:
Viết style nhanh và thống nhất.

React Router DOM:
Quản lý routing.

Axios:
Gọi API backend.

TanStack Query:
Quản lý server state, cache, loading, refetch.

React Hook Form:
Quản lý form.

Zod:
Validate form schema.
```

---

# 3. Kiến trúc frontend

Frontend dùng:

```
Feature-based MVVM-style Frontend Structure
```

Hiểu đơn giản:

```
Mỗi nghiệp vụ/màn hình lớn có folder riêng trong features/.
UI, hook, service, schema, type được tách rõ.
Component không ôm quá nhiều logic.
```

Không dùng kiểu gom tất cả vào:

```
components/
pages/
services/
```

vì khi project lớn sẽ dễ conflict và khó tìm code.

# 5. Giải thích file/folder frontend

## 5.1. `frontend/package.json`

File khai báo:

```
Tên project frontend
Script chạy project
Dependency
Dev dependency
```

Ví dụ script:

```json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc && vite build",
    "preview": "vite preview"
  }
}
```

Dùng:

```bash
npm install
npm run dev
npm run build
```

---

## 5.2. `frontend/package-lock.json`

File khóa version dependency khi dùng npm.

Ý nghĩa:

```
Đảm bảo các thành viên cài dependency giống nhau.
Giảm lỗi "máy em chạy được, máy anh không chạy được".
```

File này nên commit nếu team dùng npm.

---

## 5.3. `vite.config.ts`

File cấu hình Vite.

Có thể dùng để cấu hình:

```
React plugin
Path alias
Dev server
Build option
```

Ví dụ alias:

```
@ → src
```

Sau này có thể import:

```tsx
import { axiosClient } from "@/shared/api/axiosClient";
```

thay vì đường dẫn dài.

---

## 5.4. `tsconfig.json`

File cấu hình TypeScript cho frontend.

Nó quy định:

```
Type checking
JSX mode
Path alias
Strict mode
Module resolution
```

Không sửa tùy tiện nếu không hiểu, vì có thể làm project build fail.

---

## 5.5. `tsconfig.node.json`

File cấu hình TypeScript cho môi trường Node/Vite config.

Thường dùng cho:

```
vite.config.ts
tooling files
```

---

## 5.6. `index.html`

HTML gốc của Vite app.

Có div root:

```html
<div id="root"></div>
```

React app sẽ mount vào đây.

Không viết UI page trực tiếp trong `index.html`.

---

## 5.7. `.env.example`

File mẫu biến môi trường.

Ví dụ:

```

```

File này được commit.

Không commit:

```
.env

```

## 5.8. `src/main.tsx`

Entry point của frontend.

Nó render React app vào DOM.

Ví dụ:

```tsx

  <React.StrictMode>
    <AppProviders>
      <App />
    </AppProviders>
  </React.StrictMode>
```

Không viết logic nghiệp vụ trong file này.

## 7.1. `shared/api/axiosClient.ts`

File cấu hình Axios dùng chung.

Nhiệm vụ:

```
Set baseURL
Set timeout
Gắn Authorization header sau này
Xử lý response chung
Xử lý error chung nếu cần
```

Base URL lấy từ:

```
VITE_API_BASE_URL
```

Không hard-code:

```tsx
"http://localhost:8080"
```

trực tiếp trong service.

---

## 7.2. `shared/api/endpoints.ts`

Chứa endpoint constants.

Ví dụ:

```tsx

    SUBMIT: "/api/teacher/kyc",
```

```
Tránh gõ endpoint rải rác.
```

# 11. Quy tắc xử lý messageCode

Backend trả:

```json
{
  "success": false,
  "messageCode": "KYC_NOT_APPROVED",
  "message": "Teacher KYC is not approved.",
  "data": null
}
```

Frontend map:

```
KYC_NOT_APPROVED
→ "Bạn cần hoàn tất KYC trước khi tạo khóa học."
```

Không parse text `"Teacher KYC is not approved."`.

Lý do:

```
Sau này đổi tiếng Việt/tiếng Anh không ảnh hưởng logic.
Message code khớp với MSG trong SRS.
Dễ test và dễ bảo trì.
```

# 15. Nguyên tắc frontend cho team

```
1. Không code trực tiếp trên develop/main.
2. Mỗi Jira task có một feature branch.
3. Code đúng feature folder.
4. Không nhét tất cả vào shared/.
5. Không gọi API lung tung, dùng axiosClient.
6. Không hard-code API URL.
7. Không parse raw error message, dùng messageCode.
8. Trước PR phải chạy npm run build.
9. CI xanh mới merge.
10. Nếu sửa app/router.tsx hoặc shared/ thì báo leader.
```
