# ManabiHub source map for defense

This is the shortest path to understanding the system. Do not read the project
class by class. Follow one business request from the screen to the database,
then repeat for each actor.

## The one request pattern used throughout the project

```text
React route/page
  -> feature service (Axios)
  -> Spring controller
  -> business service
  -> repository
  -> PostgreSQL
```

Cross-cutting layers sit around that path:

- `frontend/src/shared/auth` and the React layouts protect client routes;
- `backend/.../security/config` rechecks JWT roles and live Teacher/Admin state;
- `backend/.../common/exception` converts failures to the common API envelope;
- `backend/src/main/resources/db/migration` is the only owner of schema changes;
- external providers are adapters around Google OAuth, VNPay, VNPT/registry,
  SMTP, and the OpenAI-compatible AI endpoint.

If the UI hides a button, that is convenience. The backend controller/filter
is the real security boundary.

| Actor | Main responsibility | Frontend | Backend |
|---|---|---|---|
| Public/Student | discover, buy, learn, review | `features/catalog`, `checkout`, `learning`, `ai-chat`, `course-reviews` | `course`, `order`, `payment`, `learning`, `ai`, `review` |
| Teacher | KYC, build/publish, teach, withdraw | `features/kyc`, `course-builder`, `writing-review`, `my-wallet` | `kyc`, `course`, `finaltest`, `writing`, `wallet`, `payout` |

## Eight business flows worth knowing

### 1. Authentication and authorization

- Public users authenticate with Google OAuth; callback/session handling starts
  in `frontend/src/app/pages/AuthCallbackPage.tsx`.
- Internal admins use `AdminAuthController` and `AdminAuthServiceImpl`.
- `SecurityConfig`, `TeacherEligibilityFilter`, and
  `InternalAdminRoleFilter` enforce server-side access.
- Admin JWTs contain a role, but the live database role is checked again. A
  changed role therefore invalidates the old session.

### 2. Teacher KYC

- Screen/API: `features/kyc` -> `TeacherKycController`.
- Core rules: `TeacherKycService` and `TeacherIdentityClaimService`.
- A valid identity/certificate can auto-approve. Manual Course Manager work is
  for exceptions, not every valid applicant.
- `KYC_IDENTITY_SECRET` produces stable HMAC fingerprints for duplicate
  identity detection. It is generated by the team, not obtained from VNPT.

### 3. Course authoring, approval, and publishing

- Teacher screens: `CourseDraftPage`, `CourseBuilderPage`,
  `FinalTestConfigPage`, and `TeacherCoursesPage`.
- APIs: `TeacherCourseController`, `TeacherCourseBuilderController`,
  `FinalTestController`.
- `CourseValidationServiceImpl` returns the publication checklist.
- Teacher submits for review; Course Manager decides through
  `AdminCourseApprovalController`; Teacher publishes an approved course.

### 4. Purchase, VNPay, enrollment, and escrow

- Student creates an `Order` before payment.
- `PaymentController` receives the signed VNPay IPN; the browser return URL is
  not trusted as payment proof.
- Successful idempotent confirmation creates enrollment and escrow.
- `EscrowClearingJob` releases eligible funds after
  `ESCROW_HOLDING_DAYS`; the value comes from System Settings.

### 5. Learning, assessment, writing, and AI

- `StudentLearningController` serves lesson blocks and progress.
- `StudentAssessmentController` owns quizzes/final tests;
  `StudentCertificateController` owns certificate eligibility/creation.
- `StudentAiChatController` and writing assistance call an OpenAI-compatible
  provider only after enrollment/lesson eligibility checks.
- AI output is a suggestion, never an official grade or Teacher decision.
  Provider operations are explained in `docs/AI_PROVIDER_RUNBOOK.md`.

### 6. Teacher wallet, withdrawal, and payout

- Escrow release moves revenue into the Teacher wallet.
- A withdrawal uses `WithdrawalServiceImpl`: runtime minimum threshold, wallet
  lock, pending/monthly rules, OTP consumption, encrypted bank snapshot,
  balance reservation, then notification after transaction commit.
- `PAYOUT_SECURITY_SECRET` is a stable team-generated root secret for AES-GCM
  encryption and HMAC fingerprints/OTP hashes. It is not a VNPay credential.
- Finance Manager decisions use `AdminPayoutController` and settlement/
  reconciliation services.

### 7. Public Teacher profiles and verified reviews

- Public discovery: `PublicTeacherProfileController` and
  `PublicTeacherProfileServiceImpl`.
- Only privacy-safe Teacher fields and published courses are exposed.
- `CourseReviewServiceImpl` ties one editable review to an eligible
  Student/course pair. Public aggregates use real persisted reviews.

### 8. System administration

- `SystemAdministrationController` exposes the 14 editable runtime settings and
  internal accounts.
- `SystemSettingValueService` is the read path used by course, refund, escrow,
  payout, AI, and admin-login rules.
- `SystemAdministrationServiceImpl` requires a reason, records before/after
  audit data, prevents self-role change, and protects the last System Admin.
- Secrets and provider credentials are deliberately not editable from this UI.

## Database and migration rules

- PostgreSQL schema starts in `V001`/`V002`; later files are ordered business
  changes.
- Never edit a migration already applied anywhere. Add a new version instead.
- Release candidate order is `V038` payout security, `V039` reviews, `V040`
  system administration, `V041` escrow default, `V042` demo-account hardening.
- JPA uses `ddl-auto=validate` outside tests; Flyway owns production schema.

## Configuration: what you obtain and what you generate

| Value | Source |
|---|---|
| Google client ID/secret | Google Cloud Console OAuth credentials |
| VNPay terminal/hash | VNPay merchant/sandbox portal |
| AI base URL/API key/model | chosen OpenAI-compatible provider |
| SMTP username/app password | mail provider |
| Database URL/user/password | AWS RDS/Elastic Beanstalk |
| `JWT_SECRET` | generate once; rotation logs everyone out |
| `KYC_IDENTITY_SECRET` | generate once and keep stable |
| `PAYOUT_SECURITY_SECRET` | generate separately and keep stable |

Generation and AWS placement are documented in `docs/AWS_DEPLOYMENT.md`.
Never put secret values in Git, Jira, slides, screenshots, or a presentation.

## Ten-day learning and defense schedule

1. Day 1: run locally; trace public catalog -> course detail -> PostgreSQL.
2. Day 2: trace Google/Admin auth and the three backend security filters.
3. Day 3: trace KYC -> course draft -> approval -> publish.
4. Day 4: trace order -> VNPay IPN -> enrollment -> escrow.
5. Day 5: trace learning -> progress -> assessment -> certificate.
6. Day 6: trace AI chat/writing provider contracts and failure behavior.
7. Day 7: trace wallet -> withdrawal OTP -> payout settlement.
8. Day 8: trace reviews, public Teacher profile, and System Settings.
9. Day 9: rehearse the demo using `RELEASE_CANDIDATE_HANDOFF_2026-07-28.md`.
10. Day 10: rehearse architecture/risk questions; stop adding features.

Use the remaining time for SRS/SDS correction, slides, and repeated presentation
practice. New code after code-freeze should be limited to demonstrated P0 bugs.
